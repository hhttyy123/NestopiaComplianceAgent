# 阿里云快速部署

实际目标：Ubuntu 20.04，2核4GB，公网8.145.59.194，域名catal.online。截图系统盘20GB且已用93.82%，先排查或扩容，建议为镜像构建留至少8GB可用空间。不要直接清理未知目录、Docker卷或现有业务。

先在服务器执行只读检查：

```bash
df -h /
docker --version
docker compose version
sudo ss -lntp | grep -E ":(80|443|3000)\\b"
```

Ubuntu20.04已不在Docker当前官方受支持安装系统列表；有现成Docker时先检查版本，未安装时先确认安装方案，不要直接套用24.04安装命令或重装现有服务器。中国内地地域需确认catal.online备案及阿里云接入状态。

这份步骤面向已有Linux ECS。Windows Server请先确认系统再使用对应方案，不要直接执行下面的Linux命令。

## 1. 准备服务器和域名

在阿里云控制台给ECS安全组放行TCP 80、443；SSH 22只允许管理员IP。不要开放3000。将你使用的域名A记录解析到ECS公网IP。中国内地服务器上线网站需要ICP备案；香港及海外地域不适用这一内地备案要求。参见[阿里云建站说明](https://www.alibabacloud.com/help/zh/ecs/user-guide/build-a-website/)。

HTTPS配置需要一个可解析域名，当前包没有开放裸IP无密码部署。

## 2. 安装Docker

登录ECS，确认系统及Docker：

```bash
cat /etc/os-release
docker --version
docker compose version
```

未安装时按[阿里云Docker安装文档](https://www.alibabacloud.com/help/zh/ecs/user-guide/install-and-use-docker)中与你系统对应的部分安装Docker Engine和Compose v2。Ubuntu也可用[Docker官方说明](https://docs.docker.com/engine/install/ubuntu/)。已有Docker可跳过，不必重装系统。

## 3. 从本地上传发布包

在你本机PowerShell执行，将用户名和IP改成实际值（用户名可能是root或ecs-user）：

```powershell
scp D:\NestopiaComplianceAgent\output\nestopia-vps-release.tar.gz 用户名@服务器公网IP:/tmp/
```

在服务器执行：

```bash
sudo mkdir -p /opt/nestopia
sudo tar -xzf /tmp/nestopia-vps-release.tar.gz -C /opt/nestopia
cd /opt/nestopia
sudo cp deploy/production.env.example .env.production
sudo chmod 600 .env.production
openssl rand -hex 24
sudo nano .env.production
```

将下列值改为实际信息；ACCESS_PASSWORD填上一步生成的密码，API密钥只在服务器填写：

```dotenv
APP_DOMAIN=catal.online
APP_ORIGIN=https://catal.online
ACCESS_USER=nestopia
ACCESS_PASSWORD=至少20字符的随机密码
DEEPSEEK_API_KEY=你的DeepSeek密钥
DEEPSEEK_MODEL=deepseek-flash
```

nano中Ctrl+O、回车保存，再Ctrl+X退出。不要把.env.production发给别人。本包不包含本地项目记录或密钥，上线后是空工作空间；真实案例填写数据在docs/cases。

## 4. 启动

```bash
sudo docker compose config --quiet
sudo docker compose up -d --build
sudo docker compose ps
sudo docker compose logs --tail=60 app caddy
```

构建需要能访问容器镜像仓库、npm和Debian软件仓库。网络不通时根据实际错误处理，不要使用来历不明的镜像站。首次证书申请需要DNS已生效、80/443可访问且没有其他服务占用这些端口。

浏览器打开 `https://你的实际域名`，用户名nestopia，密码为ACCESS_PASSWORD。进入后跑一份真实项目；刷新确认记录还在。当前为共享工作空间，拿到密码的人可查看全部记录。

## 5. 最必要的维护

```bash
cd /opt/nestopia
sudo docker compose logs --tail=100 app
sudo docker compose exec -T app npm run backup
sudo mkdir -p backups
sudo docker compose cp app:/app/data/backups/. ./backups/
```

将backups另外下载保存，里面含数据库和原始PDF。正常重启使用 `sudo docker compose restart`；不要执行 `docker compose down -v`，它会删除持久化卷。

启动后若无法访问，依次核对域名解析、安全组80/443、系统防火墙、容器状态、Caddy日志。若已有宝塔/Nginx占用80/443，先协调现有网站反向代理，不能直接停止其他网站。

本机已验证生产构建、类型、HTTP、备份恢复及31项自动检查；没有运行Linux Docker引擎，所以首次容器构建和公网TLS仍须在ECS上实际确认。AI报告是有引用的辅助检查，长决定书最终结论仍可能漏读，待核实项不能当作政府批准。
