# Apple风格界面修订记录

日期：2026-11-15。目标：从通用后台改成内容优先的系统应用体验。

## 研究依据

- [Apple HIG · Materials](https://developer.apple.com/design/human-interface-guidelines/materials)：导航与操作使用独立材质层；正文不铺玻璃。
- [Apple HIG · Typography](https://developer.apple.com/design/human-interface-guidelines/typography)：字号、字重和颜色表达信息层级；优先可读性与系统字体。
- [Apple HIG · Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)：宽屏侧栏、窄屏紧凑导航；可收起侧栏。
- [Apple HIG · Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars)：顶层位置导航保持稳定，移动端底部悬浮，图标配文字。
- [Apple HIG · Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)：单一主要操作、清楚的按压反馈、足够点击区域。
- [WWDC25 · Get to know the new design system](https://developer.apple.com/videos/play/wwdc2025/356/)：粗体左对齐标题、按语义分组、控件与内容分层以及跨尺寸连续性。

## 具体变化

| 上一版问题 | 本次处理 |
|---|---|
| 宣传横幅抢占首屏，系统像介绍网站 | 移除横幅、轨道装饰和悬浮文案；项目成为第一主体 |
| 过多微小字、灰蓝文字与卡片 | 采用清楚的黑色标题和正文，减少容器层级与装饰边框 |
| 所有圆角/阴影近似，缺少秩序 | 内容表面保持不透明；材质集中于导航、工具栏与临时sheet |
| 指标像企业报表，数值与语义松散 | 参考Reminders集合入口，彩色圆形符号、数量与状态形成同一可点击单元 |
| 桌面与手机只是压缩同一布局 | 桌面使用内嵌侧栏，手机使用带文字的悬浮底部导航与单列分组 |
| 弹窗仍是缩小的网页表单 | 桌面居中面板；手机使用底部sheet、固定操作区与17px输入 |

## 实现约束

- 字体采用Apple系统优先的系统栈；Windows使用本地后备字体，不分发San Francisco字体文件。
- Web的blur、透明度和高光仅近似Apple材质；不宣称复现原生实时折射渲染。
- 不增加假系统窗口按钮，不复制苹果商标，不用OS装饰代替实际功能。
- 导航、状态入口、搜索、编辑、审查、来源与审核意见均保持真实功能。
- 支持减少动态效果和减少透明度偏好；移动端输入不小于16px，主要点击目标不小于44px。
- 原知识、项目、历史报告与人工意见不因换肤重置。

样式入口：src/app/apple.css。页面与状态交互：src/components/workspace.tsx。

## 第二轮：右侧内容收敛

用户认可侧栏，但指出右侧缺少质感、图标与文字着色不合适，整体不够克制。本轮保留侧栏，右侧参考设置的中性分组及App Store的内容行：

- 右侧改为白色工作面，浅灰 inset 分组；不再将整页内容做成彩色卡片。
- 四种状态合并为同一统计组，不使用彩色背景和重复图标。
- 项目入口使用自绘图纸档案缩略图，保留轻微纸张边缘与阴影；操作图标保持单色。
- 状态以文字和小圆点表达，不使用大面积绿/蓝/橙标签。
- 删除宣传性说明和重复分组标题，保留项目数量、待处理数量及法规版本等真实信息。
- 蓝色集中于可操作元素；普通说明与专业状态不借蓝色强调。

右侧样式补充入口：src/app/content.css。补充参考：[Apple HIG Color](https://developer.apple.com/design/human-interface-guidelines/color)、[Apple HIG Icons](https://developer.apple.com/design/human-interface-guidelines/icons)、[App Store](https://apps.apple.com/us/iphone/today)。

ui-ux-pro-max本地技能中的scripts为指向缺失目录的占位文本，设计系统CLI不可执行。本次依照该技能的可读性、触控及层级清单，并直接以Apple官方规范作为设计依据。

## 材质与克制的进一步研究

补充来源：[Meet Liquid Glass，WWDC25](https://developer.apple.com/videos/play/wwdc2025/219/)、[Get to know the new design system，WWDC25](https://developer.apple.com/videos/play/wwdc2025/356/)。以下区分官方原则和本项目的设计判断。

### 官方原则

1. 材质是层级关系。Liquid Glass属于控制及导航层，内容层使用普通材料，不能为了表现玻璃把所有正文容器都透明化。
2. 新玻璃具有lensing（透镜式光线偏折）与多层自适应效果；高光、阴影、色调随背景、形状、尺寸及交互变化。固定透明度加blur只能近似部分外观。
3. 圆角具有同心关系：内层圆角根据外层圆角与内边距调整，结合视觉校正；不是统一给所有元素相同半径。
4. 字体层级由字号、字重、颜色与对齐共同构成，强调易读，避免小字配过轻字重。
5. 应用图标与界面符号职责不同。应用图标可表现丰富材质；界面符号强调简单、相同视觉重量、光学居中并与文字协调。
6. 颜色需要稳定的语义，图标也不靠随意着色表达精致。克制不意味着所有内容只能用灰色。
7. 动效解释关系：操作从触发位置展开，控件反馈即时，状态变化保持连续。安静的静止状态和响应时的表现一起组成质感。

### 本项目判断

- 设置适合作为主体结构参考：可读、紧凑、同组内容放在一起，重点在精确排版和表面关系。
- App Store适合参考项目行的比例、标题与副标题关系、内容缩略图及操作按钮的分量。
- 游戏应用可参考内容主导、工具浮于内容之上的关系；其大幅游戏封面和氛围光不直接移植到合规工具。
- 当前不应为每个数字或状态另画一套装饰图标，也不应把“没质感”简单理解为继续增加边框、阴影或浅灰底色。
- 没有真实项目图纸时，应该优先用一致、简洁的文件符号。自行绘制的微型平面图无法替代真实内容资产，仍需审查是否增加无意义细节。
- 下一轮验收先检查：第一眼焦点、明暗层次、字号比例、间距与圆角关系、图标视觉重量、状态语义、滚动/弹出/按压反馈；最后才微调装饰。

## 第三轮：全局玻璃材质（用户最新要求）

本轮侧栏也参与修改，覆盖前一轮“侧栏不变”的取舍。

- 增加低饱和的环境底色，使玻璃侧栏有背景可透；侧栏采用更低的不透明度、白色边缘高光及两级柔和阴影。
- 桌面阅读区使用独立的圆角表面；顶部工具栏、分段控件、主要入口和临时弹窗增加玻璃层的高光与透明效果。
- 手机底部导航使用相同材质，正文与审查条目维持清楚、不透明的阅读表面。
- 导航图标换为一致的自绘简洁符号；项目入口改为文件符号，不再伪造微型图纸预览。工作空间标记采用N字形，不代表公司官方商标。
- 弹窗使用唯一标题关联，并让Escape关闭走同一受控处理，保留保存期间的状态约束。
- 维持减少透明度、减少动态效果和增加对比度的后备显示。

材质样式入口：src/app/glass.css，位于布局与内容样式之后加载。

本轮验证：33项领域/持久化测试通过；TypeScript检查通过；生产构建通过；隔离HTTP流程与重启持久化验收通过。浏览器预览连接不可用（原生管道与浏览器宿主均无法连接），因此尚未完成本轮桌面与窄屏截图验收，不宣称视觉还原已确认。

## 第四轮：核心流程收敛

用户确认以“录入项目 → 看到障碍 → 明确下一步”为核心，保留现有玻璃材质，减少常驻功能区。

- 项目列表移除统计卡片和法规推荐区，保留新建、列表、搜索和必要筛选；行内优先显示位置与状态。
- 详情改为单列，结论附简短原因；下一步按冲突、缺失、专业核实排序，直接进入项目资料填写。
- 合并原待办与逐项审查，避免同一问题出现两次；原因、法规依据及AI解释在对应事项中展开。已完成检查整体默认收起。
- 历史报告、审核记录及许可参考放入项目“更多”；知识维护与说明放入工作空间“更多”，保留现有数据和操作能力。
- 未核实的许可与周期不在主报告常驻显示，仍可在报告信息中按需查阅。意见不会修改原始结论，事项入口自动关联意见记录。
- 样式入口为src/app/focus.css；本轮不新增动画或装饰图标。保留键盘焦点、低透明度及高对比度后备样式。

本轮浏览器宿主和原生管道仍不可用，尚未做桌面与手机截图验收；程序检查结果记录在开发进度中。
