# 课题三：交付范围与人机边界

依据原始课题第23至26页，目标是缩短报价前“能不能建、怎么报批”的查询过程，并把这次查过的资料和经验保留下来。当前真实验收重点为美国Maryland州、Montgomery County、独立ADU。Pergola、阳光房及其他美国地区可输入并调查，不冒充已逐区验收。

输入产品、建设方式、尺寸、用途、地址与地块条件；系统预设能否建设、许可和材料、官方周期、报价前缺口。AI搜索官方来源，保存原文版本，分析适用性并提供可回看的引用。输出分为能否建设、许可、周期；冲突、未知与建议归组，行动最多3条。追问保留父报告，纠错与处理结果进入后续经验。

Agent停在报价前建议：没有主管辖区、地块事实或现行证据，就明确未知。交给用户补充地块条件，或向实际受理部门核实。没有合规经理或PE时也不能把未知改成通过。当前不代替审批，不自动递交材料、作报价授权或工程签章，避免未经授权的真实法律和施工承诺。

为下次更快回答，最少保存结构化输入、查询与检查时间、官方原文和版本、引用定位、报告和缺失项、用户反馈及当次实际使用的经验。经验用于提示遗漏，仍须以适用证据判断；不是把上次AI回答作为法规。

错误由用户阅读原文或实际处理反馈发现；结构、引用缺失或逐字不匹配由程序先拦截。纠错只追加，旧报告保留；下次带入纠错并停止复用原行动建议。不能承诺完全杜绝语义或法律解释错误。

这轮优先实现单用户可跑通的上述链路、结构化表单与报告、引用、缓存、经验及透明执行记录。明确不做全美法规全量采集、政府自动报批、完整工程审查和多人权限。地图只提供地址定位入口，不以地图证明分区。这样先验证一条能支持报价前调查且可复用的主干。

如果见到合规经理或PE，第一句问：“您作出可报价判断前，必须确认哪项地块事实，依据哪份现行文件？”
