# Nestopia · 课题三答辩准备与项目说明

日期：2026年11月16日

依据：项目中的《四个课题(1).pdf》课题三部分（PDF实际第16—19页，对应幻灯片23—26页）。下面的问题按原课题含义整理，非逐字引文；实现情况以本次发布版为准，不能套用早期自查文档中的旧状态。

## 一、开场介绍（可直接讲）

我做的是面向Nestopia报价前场景的建筑合规管理Agent。用户输入项目地址、产品和尺寸，系统查询公开官方资料，生成建筑可行性评价、许可与材料清单，以及有依据的流程估算。每个判断可以回看引用原文，查过的资料和用户纠错会保存，供后续项目复用。

这版先聚焦美国马里兰州Montgomery County、由县级部门受理的新建独立ADU，不扩展到全美或其他产品。目标是让第一次调查形成下一次可以使用的资料与检查经验，而不是只生成一段聊天回答。

## 三、课题要求准备的四个问题

### 问题1：Agent应该在哪一步停下？交给谁？

**回答：停在报价前的合规调查建议，不自动批准报价、施工或许可。**

缺少地址、分区、尺寸等事实时，请用户补充；法规适用或政府办理问题，向实际受理部门核实；结构、基础和消防等专业设计问题由具备相应资质的设计者确认。如果只有我和工具，也可以继续查公开材料、列出缺口，但不能把未核实事项改为通过。

这样设计的原因是：搜到资料不等于确认某地块满足条件，AI不能代替政府许可或工程责任。

### 问题2：如果要下次更快给答案，最少需要保存什么？

**回答：保存原始项目事实、来源版本、结论与引用、缺失条件、反馈及检查结构。**

| 保存内容 | 用途 |
|---|---|
| 产品、建设方式、县州、地址、尺寸、用途及地块条件 | 知道当时判断的前提，避免套用到不同项目 |
| 查询词、来源URL、抓取时间、内容哈希、原文段落 | 减少重复查询，追溯当时依据 |
| 原始官方PDF及提取文本 | 核对原文、版式与最终命令 |
| 评价状态、条文、理由和引用关系 | 知道结论从哪里来 |
| 许可材料、阶段依赖与时间依据 | 下次复用调查结构，而不是猜完整流程 |
| 纠错及实际办理反馈 | 识别旧建议的问题，后续重新查证 |

查询缓存6小时，原文缓存24小时；短时不可读来源缓存5分钟。用户可主动跳过缓存重新查询。缓存减少重复工作，不保证瞬间返回，也不是实时法规更新监测。

### 问题3：如果Agent答错了，谁先发现？怎么避免再次答错？

**回答：程序先查可机械验证的问题，独立AI再复核证据适用性，用户和实际办理反馈补充纠错。**

1. 程序检查字段结构、引用是否存在且与原文匹配、数值与单位是否一致、尺寸比较是否成立、流程依赖是否成环。
2. 独立AI复核原始输入、条文、辖区、历史案例、材料和时间口径。它是另一轮模型检查，不是人工审核或完全独立的权威机构。
3. 用户可打开原文核对，提交附依据链接的纠错。收到纠错的报告不再沿用原行动建议；同范围后续项目会参考该纠错并重新查证。
4. 已发现的软件错误补充回归检查；未完成复核或执行失败的草稿不作为正式报告展示。

不能承诺不再犯错。当前真实测试仍发现长决定书最终命令可能漏读；这类问题需要继续改善选段、抽取与案例验证。

### 问题4：如果只有三天，优先做什么？明确不做什么？

**回答：先跑通一个县、一种产品的有据调查闭环。**

| 时间 | 优先交付 |
|---|---|
| 第一天 | 明确MD蒙县新建独立ADU范围，跑通输入、官方资料检索及存档 |
| 第二天 | 完成20维评价、许可材料和阶段流程，加入引用及事实校验 |
| 第三天 | 做真实案例比对、纠错复用、稳定性检查与部署交付 |

明确不做：全美全量法规库、所有建筑产品、自动政府递交、审批状态同步、专业图纸审查、PE签章、多租户权限系统。原因是短时间应优先验证核心价值与可追溯性，不能用功能数量掩盖判断质量。

## 四、课题附加准备问题

### 见到合规经理或PE，第一句话问什么？

“您作出可报价判断前，必须先确认哪项地块事实，依据哪份现行文件？”

目的：找出真实业务的关键阻断项，再反推表单、证据来源和停止边界。当前没有实际合规经理或PE访谈记录，不能声称已经专家验证。

### 做了什么、拒绝做什么、为什么？

做了报价前资料调查、结构化评价、许可材料组织、阶段估算和经验参考。不作批准、签章、自动递交或开工承诺，因为这些需要更完整事实、适用法律确认、专业资质及真实授权。

## 五、AI到底负责什么？规则负责什么？

AI负责拆解问题、生成检索计划、阅读资料、分析适用性、组织许可清单、提出有据估算，以及复核证据与结论。

程序负责范围限制、字段验证、检索缓存、原文保存、引用核对、尺寸单位换算与数值复算、流程时间计算和结果持久化。

本版不是把几个固定法规阈值写成脚本来替代AI判断。法律限制由AI从当次证据提取，程序复算提取后的数值关系；但提取是否完整、解释是否正确仍可能有错。

## 六、信息流程（从上到下讲）

```text
输入：产品、地址、尺寸、用途与地块条件
                    ↓
读取相关历史检查结构及纠错反馈
                    ↓
AI规划检索问题
                    ↓
查询官方来源／检查近期缓存
                    ↓
获取网页或官方PDF，保存原文与版本
                    ↓
AI分析建筑条件、许可材料和流程时间
                    ↓
程序校验＋独立AI证据复核
                    ↓
输出：建筑可行性／许可与材料／预计流程
                    ↓
保存报告、材料状态、反馈与经验关联
```

失败会保存错误和已取得的资料，不生成固定替代答案。程序显示“完成”表示流程执行完毕，不表示结论已得到政府或专业人士确认。

## 七、为什么用20项评价和9类许可？

20项评价分别是：主管辖区、土地分区、建筑用途、主屋条件、建筑面积、地块覆盖率、建筑高度、退界与间距、停车与出入、消防与救援、结构与基础、供水、排污、供电、洪泛与排水、历史保护、生态与树木、地役权、私人契约与HOA、通行与无障碍。

设计逻辑：先确认谁管及是否准入，再检查尺寸和选址，再检查工程与公用设施，最后检查特殊地块和私人限制。固定顺序让每次报告可比较；它是检查框架，不意味着每个地块的全部法规已经覆盖。

9类许可分别是：前置审批、建筑、给水、排污、电气、燃气、暖通、消防、场地与排水。

注意：这是9个业务分组，不是当地恰好9个组织部门。每类可能涉及多个受理单位；是否适用、材料和顺序要按当地资料判断。

状态解释：通过＝该单项在已填事实与当前依据下符合；不符合＝有条款与理由支持；待核实＝事实或依据不足；不适用＝有理由不触发。不能因为有一项通过就宣布整个项目可以开工。

## 八、数据、提示词和经验保存在哪里？

| 内容 | 当前保存方式 |
|---|---|
| 项目输入、报告、材料勾选和阶段断点 | SQLite的research_runs.payload |
| 查询记录与缓存 | research_queries |
| 来源及不可变原文版本 | research_sources、research_source_versions |
| 纠错与处理反馈 | research_feedback |
| 实际模型请求、输出和校验记录 | research_trace；不保存隐藏推理链 |
| 原始官方PDF | DATA_DIR/sources/内容哈希.pdf |
| 数据库本体 | DATA_DIR/nestopia.sqlite；本地默认data/nestopia.sqlite，容器为/app/data/nestopia.sqlite |
| 主提示词 | src/server/prompts.ts |
| 独立复核提示词与验证 | src/server/quality.ts |
| 固定输出结构 | src/domain/evaluation.ts |

经验按同产品、同县州、同建设方式参考最近4份报告的检查结构和反馈，支持不同地址。它属于检索与上下文复用，没有微调模型，也没有自动形成经权威认证的法律知识库。

开发者页面和公开接口已移除，后台审计记录仍保存。部署版是一个共享工作空间，不是多用户数据隔离系统。

## 九、项目价值和差异化怎么说？

核心价值是缩短报价前反复查资料和整理依据的工作，并让调查结果可复查、可纠错、可复用。与普通聊天的区别在于：明确支持范围、固定评价框架、保存项目原始事实、引用指向原文、保留来源版本、记录反馈与经验关联。

不能直接声称已节省某个百分比时间或达到某个准确率，目前没有充分测量。后续应记录首次与复用查询耗时、关键条件覆盖率、错误率、引用有效率及最终案件结果匹配情况。

## 十一、哪些能用，哪些仍需完善？

已经实际实现：结构化输入、真实联网检索、官方PDF直读、原文存档、报告引用、缓存、反馈、经验参考、材料保存、项目删除恢复及部署配置。当前用户流程不使用内置业务样例、固定报告或失败后的虚构结论。

仍需完善：法律适用准确性、许可材料完整性、长文书最终结果抽取、足够多独立地块的验证、总周期预测。未知的准备、补件或发证时间不能用首轮审查时长代替。地图目前是定位链接，不是地块GIS或分区自动核验。

尚未实现：自动报批、审批状态同步、专业工程审核、多租户账号隔离。历史demo归档不进入运行与发布包，测试桩只验证软件行为；不能说仓库历史上完全没有demo代码。

当前验证记录：31项自动检查通过、类型与生产构建通过、HTTP检查及备份恢复通过。真实联网曾完成多轮执行并验证缓存与经验复用，也暴露过引用和最终命令漏读问题。测试通过不是法律准确率证明；公网是否上线以服务器实际部署结果为准。

## 十二、结束陈述（可直接讲）

这版完成的是一个能运行、使用真实资料、保留证据和反馈的报价前调查闭环。它把一次性的AI回答变成可复查的项目记录，并尝试让后续调查复用已有检查经验。接下来最优先做的是提高同一范围内的证据适用性和案例结果准确性，然后再逐步接入真实报批与跟踪，而不是马上扩展到所有地区和产品。
